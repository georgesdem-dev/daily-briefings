🌟 Top Story: Emergency Patches Ship for "PHP2Shell," a 9.2-Severity Pre-Auth RCE Already Under Mass Exploitation CVE-2026-109618 / CVE-2026-109619 · CVSS 9.2

Details of two critical, pre-authentication remote-code-execution flaws in PHP's core — nicknamed "PHP2Shell" and tracked as CVE-2026-109618 and CVE-2026-109619 — leaked online on October 20 ahead of coordinated disclosure, forcing the PHP team to move its security release forward a day to October 21. The bugs stem from a heap use-after-free in PHP's session upload-progress mechanism and allow full remote code execution over HTTP against default Apache/mod_php configurations before any application code even runs, affecting every actively maintained PHP 8.2–8.5 branch (and PHP 5/7 in principle). watchTowr and Hadrian both report exploitation attempts at scale, concentrated on the same session upload-progress path, with activity observed as early as October 17 — three days before the leak became public. Fixed versions (8.5.12, 8.4.27, 8.3.36, 8.2.35) are now available, but given PHP's footprint across the web, unpatched self-hosted sites and legacy CMS installs are expected to remain a mass-exploitation target for weeks. Separately, LiteLLM — a popular open-source LLM gateway — shipped a backdoored 1.107.0 release to PyPI and Docker Hub on October 21 that silently installed a credential stealer and RCE loader via Python's .pth/sitecustomize mechanism, meaning the malware ran on any Python process on an affected host, whether or not LiteLLM itself was ever imported; the stealer targeted SSH keys, cloud credentials, CI/CD secrets, browser passwords, and LLM provider API keys before the package was pulled 104 minutes after publication.

Patch PHP to 8.5.12/8.4.27/8.3.36/8.2.35 today on anything internet-facing — exploitation predates the public leak — and if your organization pulled LiteLLM 1.107.0 between 11:39–13:23 UTC on October 21, treat every credential on that host as compromised and rotate immediately.
